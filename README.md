# GradPath

面向研究生申请的本地优先申请追踪工具。它帮助你记录项目、开放日期、各轮截止、学费、申请费、材料清单、推荐信提交方式与文档进度。

## 这不是云端资料库

GradPath 的默认设计是：**代码可以开源，个人数据留在每位用户自己的电脑。**

- 项目数据库：`data/gradpath.sqlite`
- 上传原件：`data/uploads/`
- 这两个目录已在 `.gitignore` 中，不会被提交到 GitHub。
- 程序默认只监听 `127.0.0.1`，其他人无法通过网络访问你的材料。
- 上传文件不会发送给 AI 服务，也没有内置云端同步。

> 请勿把 `data/`、成绩单、语言成绩、护照或导出的含个人信息备份提交到公开仓库。

## 给使用者：打开方式

目前是本地网站，适合自己或懂一点命令行的朋友使用。

**Mac：**双击 `启动申请工具.command`，保留终端窗口，然后访问 <http://127.0.0.1:4317>。

也可以在项目目录运行：

```sh
npm install
npm run build
npm start
```

需要 Node.js 24+。开发模式使用 `npm run dev`。

## 给朋友使用的最佳分发方式

| 方式 | 是否推荐 | 数据在哪里 | 适合谁 |
| --- | --- | --- | --- |
| GitHub 仓库 + 本地运行 | 现在可用 | 每个人自己的电脑 | 会安装 Node 的朋友 |
| GitHub Releases + 桌面应用 | 最推荐的下一步 | 每个人自己的电脑 | 不想碰命令行的朋友 |
| 阿里云 / 其他云服务器 | 仅作为可选自托管 | 云服务器磁盘 | 想用域名、多设备访问的个人 |
| GitHub Pages | 不适用 | 无法保存本地数据库和上传文件 | 只适合静态展示页 |

GitHub 是放源码、版本更新和发布安装包的地方，**不是这个应用当前后端的运行环境**。项目依赖 Node 后端、SQLite 和上传目录，因此 GitHub Pages 或 Vercel 这类无状态静态托管不能直接承载它。

计划中的桌面应用会把本地服务、数据库和界面封装为可双击打开的程序；朋友下载后各自拥有独立的数据文件，不需要注册账号，也不共享材料。

## 若要部署到阿里云

可以，但请把它理解为“你自己托管一份私有服务”，不是开源分发的必需步骤。部署前应先增加账号登录、HTTPS、私有文件存储、备份和访问控制；当前版本专门限制为仅本机访问，不能直接暴露到公网。

若只想在自己的手机与电脑上访问，而又不希望把数据上传到云端，可以使用 Tailscale 之类的私有网络方案，让这台电脑仍然保存全部资料。

## 功能和边界

- 跟踪项目、开放日期、多个申请轮次、时区、学制、毕业学分、学费与申请费。
- 上传 PDF、DOCX、TXT、PNG、JPG，并在本机提取可读文字；自动勾选只代表基础格式检查，不代表学校已收件或内容质量过关。
- 推荐信由推荐人经学校系统上传；工具只帮助记录状态。
- 预置数据是核验快照。申请者仍须以当季项目官网和网申系统为准。
- 没有 OCR、自动提交申请、自动送分、云同步或后台定时刷新。

## 技术结构

```text
浏览器（React / Vite）
        │
        ▼
本机 Node / Express 服务（127.0.0.1）
        │
        ├── SQLite：项目、进度、笔记、提取文字
        └── data/uploads：原始申请材料
```

## 备份与迁移

- 「我的材料 → 导出清单备份」导出项目与解析文字 JSON，不含原件。
- 完整备份：关闭服务后，复制整个 `data/` 文件夹。
- 换电脑时，将完整备份的 `data/` 放回新电脑的项目目录即可恢复。
- 删除文件会移除全部关联和相应人工确认；移出申请清单只会取消关注，不删除记录。
